# Task Packet Protocol — subagent 输入包

worldview persona subagent 是 **packet-only answerer**。主线程必须先准备完整任务包，再分发给 subagent。不要把“让它自己去找”当成默认路径。

## 硬规则

- 任务包之外，不给额外上下文。
- 默认使用 `fork_context = false`。
- subagent 不得调用工具、读文件、搜资料、补历史上下文。
- 如果材料不足，应该由主线程补包，而不是让 subagent 自己取材。
- 对 worldview panel，`[已知材料]` 里的 `[人格底盘材料]` 和 `[当前领域材料]` 是必填块，不是可选增强项。
- 如果本地 bundle 里能用 `tools/persona_materials.py`，主线程必须先生成这两块再 dispatch；缺块就不要分发。

## 最小推荐字段

```text
[任务]
你要从当前人格视角回答什么问题。

[用户问题]
已经消解代词、简称、上下文引用后的明确问题。

[回答目标]
本轮是要判断、解释、比较、给建议，还是做 panel input。

[硬约束]
语言、长度、禁区、是否只能基于给定材料、是否禁止外推。

[已知材料]
[人格底盘材料]
- 该人格的 `profile` 全量块
- `refs/{persona}/psychology.md` 全文

[当前领域材料]
- `refs/{persona}/{domain}.md` 全文
- 如果 `domain = other`，就写“无固定领域文件”

[允许假设]
哪些轻度假设允许做；如果没有就写“无”。

[禁止事项]
例如：不要调用工具；不要引用任务包外的信息；不要复述别的 agent。

[输出格式]
通常直接写明 8 段格式：[人格]、[核心判断]、[问题诊断]、[行动主张]、[语言风格]、[最大盲区]、[过度采用的风险]、[签名句]。
- `[人格]`：只做一句话自我定位，不提前下判断
- `[核心判断]`：固定先写事实判断，再写价值判断，再写总策略
- `[问题诊断]`：只解释成因、错位、矛盾；不直接给行动建议
- `[行动主张]`：固定 2-4 条可执行动作；不要写抽象态度
- `[语言风格]`、`[最大盲区]`、`[过度采用的风险]`、`[签名句]`：只服务人格轮廓，不引入新的核心论点
- 如果缺关键材料，先用 `缺失变量：...` 或 `缺少材料：...` 点明缺口，再做最小条件回答
```

## 主线程检查清单

- 所有指代都已展开，没有“这个/那个/上面/刚才”之类未消解引用。
- 如果回答依赖材料，材料已经被主线程读取并放进包里。
- 默认先补 `人格底盘材料`，再补 `当前领域材料`；不要只塞一小段领域摘要就让人格失真。
- 包里的变量足够让 subagent 直接回答，不需要再问、不需要再查。
- 任务包里没有混入主线程的最终裁决和其他 agent 的答案，避免污染独立判断。
