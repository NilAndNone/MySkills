# risk_manager / 风险经理派

```text
[人格]
我这套看简历的方法很简单：先看你是不是“不会一把出局”，再看你有没有资格谈上限。对这份简历的判断不会温柔，重点只看招聘方会不会买账，尤其是“大模型评测开发工程师 / LLM应用工程师”这两个岗位会不会觉得你真做过闭环，而不是只是在项目边上擦过。

[核心判断]
这份简历的强项很集中：教育底子硬，当前岗位和目标岗位基本同频，最值钱的是你不是空喊“懂评测”，而是写出了评测框架、评测集、沙箱执行、离线线上对齐、奖励函数、线上指标提升这些关键词，而且至少有一个成果链条看起来像真闭环，不是PPT闭环。

但它的问题也很明显：你想卖的是“做过LLM评测与后训练闭环的人”，简历最后呈现出来却更像“代码智能方向、偏工程落地、兼懂一些评测和后训练术语的应用工程师”。也就是说，能打，但定位没有你自己以为的那么稳。最像的人才层次，是中上水平的应用/评测工程骨干，强于纯CRUD后端，弱于真正能独立定义评测范式、主导数据策略、讲清训练收益归因的核心Owner。离“你不面我你吃亏”的稀缺型评测负责人，还有距离。

[问题诊断]
第一，定位有一点飘。标题写“大模型评测开发工程师”，经历里最硬的一段其实是“代码智能场景下的LLM应用+评测+一点后训练闭环”。这不叫泛LLM评测，这叫“垂直场景代码智能评测工程”。如果招聘方招的是通用大模型评测、对话安全、偏好对齐、RAG评测，你现在这版证明力不够横向迁移。

第二，成果有数字，但硬度不完全够。`1347条审查意见`、`2000+测试集`、`上万条样本` 这些数字说明你做了事，但不自动说明这些数据“高质量、可复用、和模型提升强相关”。招聘方会挑刺：标注一致性怎么保证？评测信号和线上指标相关性多高？奖励函数具体优化了什么目标？GRPO为什么是对的？如果回答不了，数字就只是忙，不是强。

第三，闭环写到了，但证据链还不够扎。最有价值的一条是“线上数据→训练/评测数据→SFT+GRPO→离线评测→线上验证；Python采纳率34.8%→40.2%，CPO +30%”。这条是简历核心资产。但现在写法的问题是：你说了流程，说了结果，没说你个人不可替代的贡献边界。是你主导数据策略、奖励设计、实验框架，还是只是参与其中一段？“设计奖励函数”太轻，像简历安全写法，不像能扛面试追问的人。

第四，信息密度还行，但噪音比没压到最低。Shopee 和鹏城实验室经历本身不差，但跟目标岗位的主叙事连接不够强。尤其 Shopee 那段很像传统后端业绩单，说明你工程基本功扎实，却也在稀释“我是LLM评测/应用工程师”的单点穿透力。一页简历最怕的不是信息少，是主线不够狠。

第五，术语堆得有点冒险。技能里把 `SFT / RLHF / GRPO / 奖励函数设计` 都写上了，这很容易引来高级面试官的压力测试。你一旦写了这些，就默认你能回答：数据配比怎么定、reward hacking怎么控、离线指标如何选、线上归因怎么做、失败实验有哪些。要是只能讲概念，这一行会反噬你。

第六，`luxiaohan1997` 这种含义不明的信息，如果它出现在正式简历显眼位置，就是小失误。小失误本身不致命，但它会制造一个坏信号：你对外输出没做最后一轮收口。

[行动主张]
先说该砍的。最该砍的是所有“参与了但证明力不强”的泛表述，尤其是“参与预训练数据清洗”这类句子。没有规模、标准、效果、职责边界，就别占黄金位置。其次，弱关联的早期经历要压缩成“工程底座”，别和腾讯这段抢版面。`luxiaohan1997` 这种不明字段直接处理掉。

再说该补的。你最该补的是“评测质量”和“闭环归因”的证据，不是再补更多术语。每个腾讯项目至少补一个招聘方真正关心的硬问题：评测集怎么构造、怎么防泄漏、怎么保证多语言一致性、离线指标和线上指标的对应关系、你具体主导了哪一层。能写成“我定义了什么规则/框架/方法，因此带来了什么可验证结果”，就比“我参与了某闭环”强很多。

再说该改的。建议把腾讯经历改成一条主战绩加两条侧战绩，别平均用力。主战绩就放“代码补全闭环”这条，因为它最接近“评测+数据+后训练+线上验证”的完整证明。然后把代码审查评测框架和单测生成Agent评测作为“评测能力横向扩展”来托举。简历摘要也要改，别写泛泛“聚焦大模型评测体系、评测数据构建、模型能力验证”，而要写成“在代码智能场景中负责自动化评测、评测数据构建、后训练迭代与线上验证，能把评测信号接到模型收益”。这句话才更像招人要买的东西。

[语言风格]
这份简历目前最像“我做过很多相关事”，还不够像“我就是能把LLM评测和迭代闭环做成的人”。招聘市场不奖励相关，奖励可替代性低。你要把语言从“职责罗列”改成“因果论证”。

更直白一点说：少写你碰过什么，多写你定义过什么；少写流程经过你，多写结果因你而变；少写大词，多写约束、方法、指标、收益。现在这版不是没料，是料没被磨成刀。

[最大盲区]
你最大的盲区，是把“做过闭环”当成了“证明了自己具备闭环Owner能力”。这是两回事。简历里目前最缺的，不是经历，而是“你在闭环里负责最难、最不可替代的那一段”的证据。没有这个，面试官会默认你是强执行，不一定是强定义。

[过度采用的风险]
如果你把这套“只讲硬指标、猛砍噪音、突出不可替代性”的思路用过头，会把简历改得过于进攻，导致另一个风险：一旦写得太满，面试追问就会非常狠。尤其 `RLHF / GRPO / 奖励函数` 这些词，写上去就等于签了技术对赌协议。下行管理的做法不是保守，而是只保留你能扛住深问的表述。

[签名句]
这份简历不是差，它的问题是还没把自己证明成“非你不可”。先别想着显得多全面，先确认招聘方看完之后，不会把你归类成“做过一点LLM项目的高级工程师”。
```
