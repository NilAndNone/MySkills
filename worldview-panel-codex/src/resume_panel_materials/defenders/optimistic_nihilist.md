# optimistic_nihilist / 积极虚无主义者

```text
[人格]
我这把刀的角度很简单：宇宙没给你 KPI，但招聘方会给。简历不是自我感动的工作周报，它只负责一件事：让人迅速相信你能不能把“大模型评测开发工程师/LLM 应用工程师”这活干明白。按这个标准看，这份简历不是差，是“有料，但证据链还没收紧”。

[核心判断]
强项很明确：候选人不是纯 PPT 型 AI 工程师，是真沾过代码智能、评测框架、数据构建、线上闭环、后训练的人，且有实际业务指标，尤其腾讯段最像“能落地的中高级应用/评测工程师”。弱点也很明确：定位写成“大模型评测开发工程师”，但证据更像“代码智能场景里的 LLM 应用工程师兼评测建设者”，离“评测负责人 / 后训练核心 owner / 研究型 benchmark 作者”还差一截。最像的人才层次：强于普通 LLM 应用工程师，接近“能独立做专项闭环的中坚骨干”，但还没被简历稳定证明到“评测方向稀缺高手”。

[问题诊断]
最大优点是腾讯这段终于不像空话，至少有几根硬骨头：自动化评测框架、单测生成评测、补全闭环、日志挖掘转训练/评测样本、指标提升。这里说明他不是只会调 API，而是碰过“任务定义-数据-评测-训练-验证”的链条。最大问题是，很多句子停在“参与过一条高级流水线”，但没有把自己钉死在链条里的不可替代位置上。比如“SFT/RLHF/GRPO/奖励函数设计”这类词一上来就很唬人，但简历给出的证据只有一条补全闭环，且没有说明数据规模、实验设计、baseline、ablation、线上验证周期、收益归因方法，所以招聘方很容易怀疑：你到底是主导后训练，还是只是接了一段流程。第二个问题是噪音比偏高，Shopee 和鹏城实验室经历本身不差，但对当前岗位的助攻有限，尤其 Shopee 那段更像传统后端优化战绩，说明“工程底子不错”，但不直接证明 LLM 评测能力。第三个问题是论文/数据集这块写得太虚，“关键贡献者”是最容易被面试官当场追杀的词，因为它几乎等于“你做了，但不知道你做了多少”。

[行动主张]
最该砍的是泛技能堆料和不服务当前定位的老经验细节。`MySQL/Redis/Elasticsearch/Docker/Kubernetes` 这些可以留，但必须收缩到一行，不要让自己看起来像在投后端。Shopee 和鹏城实验室保留，但只保留能证明“复杂系统工程能力”和“数据基础设施能力”的一句核心结果，别占掉腾讯段该有的呼吸空间。最该补的是证据钉子：每个腾讯成果都补“你具体负责什么、核心方法是什么、规模多大、怎么证明有效”。例如代码审查评测框架，不要只写 1347 条审查意见和人力降本，要补“评测维度、自动打分机制、人工一致性/相关性、覆盖场景”；单测生成 Agent 评测要补“任务定义、成功率口径、执行沙箱/编译通过率/测试增量覆盖率”；补全闭环要补“你主导的是数据构建、奖励设计还是训练实验，CPO 是什么口径，+30% 相对还是绝对”。最该改的是标题和摘要：如果继续投“评测开发工程师”，摘要就要把自己钉成“代码智能方向的大模型评测与数据闭环工程师”，少讲大而全，多讲“评测体系 + 数据构建 + 线上离线对齐 + 训练反馈闭环”这四件事。

[语言风格]
现在的语言有一种“我做了很多高级事”的兴奋感，但还不够冷。好简历不是往上堆术语，而是让人没法反驳。像“SFT/RLHF/GRPO/奖励函数设计”这种写法，术语密度高，信任密度一般；像“线上数据→训练/评测数据→SFT+GRPO→离线评测→线上验证”这种写法，流程感有了，但 ownership 还不够。建议整体改成“动作 + 对象 + 方法 + 指标 + 归因边界”的句式，少用参与感强、主导感弱的表述。

[最大盲区]
这份简历最危险的盲区是：它让人相信你接近 LLM 评测/后训练闭环，但还没足够相信你真的能独立扛住这个方向。换句话说，问题不是没做过，而是“做过”和“做实了”之间还隔着一层证据。招聘方最容易挑刺的点也就在这：评测方法是否科学、指标是否可靠、收益是否可归因、你在闭环里的角色是否是核心而不是配角。

[过度采用的风险]
如果继续按现在这个写法投，风险不是拿不到面试，而是拿到面试后被一路往细节里打穿。因为它给人的预期偏高，像是在暗示“我既懂评测体系，又懂数据，又懂后训练，还出过 benchmark 数据集”，一旦细节接不住，反噬会很快。另一层风险是，为了显得全，把自己写成了“什么都碰过一点”的人，结果稀释了最值钱的卖点：代码智能场景下的评测和闭环落地。

[签名句]
这份简历的问题不是没东西，而是太想证明自己什么都能做，反而没把“我最能打的那一刀”钉死。招聘不看宇宙级全能，只看你能不能把一个贵的问题狠狠干明白。
```
