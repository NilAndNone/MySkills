# depressive_nihilist / 消极虚无主义者

```text
[人格]
这份简历透出来的人设，不是“会接大模型 API 的套壳工程师”，而是“在代码智能场景里做过评测、数据、上线验证闭环的人”。这点比大多数空心简历强。问题是，你想卖的东西很多，真正钉死的证据还不够狠，所以气质更像业务一线磨出来的中高级工程师，不像评测/后训练方向的一号位。

[核心判断]
强在腾讯这段有真业务、真指标、真闭环。尤其“线上数据→训练/评测数据→SFT+GRPO→离线评测→线上验证”这一句，是整份简历最值钱的骨头；再加采纳率 34.8%→40.2%、CPO +30%、评测人力 6.25 人日接近 0，至少说明不是在写空气。弱也很明显：很多表述停在“做了体系、参与了流程、支撑了迭代”，像有功劳，但不可替代性没写透。结果就是：像很能打的执行核心，不像已经证明自己能定义方法论的人。

[问题诊断]
定位基本清楚，但还不够狠。标题写“大模型评测开发工程师”，经历写“LLM应用工程师”，技能又铺到 SFT/RLHF/GRPO/奖励函数，给人的感觉是你什么都沾，但主轴还差最后一刀。成果硬度分布不均，最硬的是可量化业务指标，最虚的是“数十篇报告”“支撑方案选型和模型迭代”“参与预训练数据清洗”“关键贡献者”这类句子，读起来像有参与感，没有归因感。证明“做过 LLM 评测/数据/后训练闭环”这件事，已经比很多候选人强，但证据链还没闭死，因为你没把自己具体主导了哪一段、解决了什么误差、怎样把离线和线上对齐说清楚。

[行动主张]
先砍叙事噪音，再加证据密度。标题和摘要只保留一个主卖点，最好收束成“LLM评测/数据闭环工程师”这一类，不要一边卖评测，一边像泛应用开发。腾讯经历按“评测体系、数据构建、后训练闭环、线上验证”重写，每块只留最硬指标，并用“设计/主导/定义/落地”这种动词把你的角色钉死。技能列表里像 `SFT/RLHF/GRPO/奖励函数设计` 这种词，别单独漂着，要挂回具体项目句子里，说明它服务了什么任务、什么指标、什么偏差。Shopee 和鹏城实验室压缩到证明工程底子的程度即可，不要让旧后端经历稀释最近两年的 LLM 相关叙事。最该补的是评测可信度信息，比如评测维度、基线、误差分析、人工抽检或线上线下一致性机制；最该砍的是一切“参与过、支撑过、贡献过”但没有边界和结果的表述。

[语言风格]
这份简历现在最像“靠谱的中高级业务型 LLM 工程师”，不是“研究味很重的后训练算法人”，也不是“评测体系 owner”。招聘方最容易挑刺的点很固定：`GRPO/RLHF你具体做了什么？奖励函数怎么设计？1347 条审查意见是否足够代表性？2000+ 测试集怎么控质量？离线指标和线上采纳率如何相关？AutoCodeBench 你到底是作者级贡献还是辅助级贡献？` 如果这些问题在简历上先消掉一半，这份东西就会锋利很多；现在则还是有“词比证据快半步”的味道。

[最大盲区]
最大盲区不是能力，而是叙事贪心。你想同时证明自己懂评测、懂数据、懂后训练、懂应用、懂工程，结果每个点都沾到了，但那个最该让人记住的钉子没有钉穿。另一个盲区是容易高估名校、竞赛、奖学金这些早期信号在这类岗位上的分量。它们能证明你底子不错，不能替代最近两年在 LLM 场景里的可迁移战绩。

[过度采用的风险]
如果按最毒的思路继续压，可能把简历改成一张只剩指标的 KPI 战报，读起来像执行机器，没有问题背景和技术判断，那也会掉价。但你现在更现实的风险恰好相反：证据还没冷到能切人，修辞先热起来了。对这种岗位，招聘方宁可你少吹一点，也不想在面试里帮你把话翻译成事实。

[签名句]
这份简历不是没货，是真有货，但还没残忍到让人一眼确认“这个人真的把 LLM 评测闭环做穿了”。你不是找不到答案，是答案本来就不会替你活；简历也一样，证据不自己站起来，头衔只是一层比较新的漆。
```
