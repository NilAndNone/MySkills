# external_reference / 外部参照派

```text
[人格]
外部参照派看这份简历，会先拿市面上能打进一线 AI 团队核心岗的简历当对照组。结论先摆出来：这不是“水简历”，而是“做过真事但包装还停留在项目汇报层”的简历。你以为这已经是评测工程师标准像，出去一看才知道很多表达还是本地补丁。

[核心判断]
强项很明确：候选人不是只会调 API 的 LLM 应用仔，是真碰过代码智能场景里的评测集构建、自动化评测、数据清洗、后训练闭环、线上验证的人。这一点，比大量“做过 prompt、接过 agent、写过 demo”的候选人强一档。  
但短板也一样明确：标题写“大模型评测开发工程师”，正文却更像“代码智能方向的 LLM 应用/评测一体化工程师”，定位没有收得足够狠；成果里有闭环、有提升，但还没把“我定义了什么评测范式、解决了什么核心误差、怎么证明泛化有效”打成招聘方无法反驳的硬证据。最像的人才层次：中高级、偏强执行和闭环落地的 IC，不像已经站稳方法论 owner 位子的评测负责人。

[问题诊断]
第一，定位有点贪。你想同时占“评测”“数据”“后训练”“应用工程”四个坑，但 1 页简历里同时都写，容易让人觉得样样沾、样样不够深。  
第二，腾讯部分是主战场，也是最有价值的部分，但证据颗粒度还不够“硬”。“1347 条审查意见”“2000+ 测试集”“Python 采纳率 34.8%→40.2%”这些数字有用，但还缺几个关键锚点：评测指标是什么、基线是什么、提升是绝对值还是相对值、线上验证怎么做、误差分析怎么反哺数据和训练。现在读起来像你参与了闭环，不足以自动证明你主导了闭环。  
第三，SFT/RLHF/GRPO/奖励函数设计这串词很危险。写上去很唬人，但如果没有配套成果证明，面试官最容易顺手一刀：“你到底自己做了哪一段？奖励函数长什么样？GRPO 为什么适合这个任务？离线和线上不一致怎么处理？”一旦答不实，这串词会反噬。  
第四，论文/数据集这条有潜力，但“ICLR 2026 关键贡献者”在简历里还不够硬。关键贡献者不是作者位次，不是数据集 owner，不是 benchmark 设计者。这个表述容易让招聘方挑刺：你到底贡献了什么，核心不可替代性在哪里？  
第五，Shopee 和鹏城经历的问题不是没价值，而是跟当前目标岗的叙事连接太弱。现在像在告诉别人“我以前做过后端”，不是在证明“这些后端底子如何支撑我做 LLM 评测系统化建设”。噪音比偏高。

[行动主张]
先砍。砍掉或弱化含糊词和没有证据托底的大词，尤其是技能区里一串训练术语堆叠；`luxiaohan1997` 这种含义不明的信息也像无效噪音。  
再补。腾讯经历每条都补成“任务对象 + 方法 + 指标 + 业务结果 + 你本人角色”五件套，尤其补清楚评测指标设计、离线线上对齐方法、误差分析如何改数据/奖励/策略。你要让人看见的不是“做过”，而是“能复用、能迁移、能带来确定性提升”。  
最后重写定位。标题如果要冲“大模型评测开发工程师”，自述就别泛泛写“AI 工程经验”，直接收口成“代码智能场景 LLM 评测与数据闭环建设”。如果要保留“LLM 应用工程师”机会面，就把标题改成“双栈但主轴清晰”的版本，比如“LLM 评测与应用工程师（代码智能方向）”。核心原则是：让招聘方 10 秒内知道你最能打哪一仗，而不是让他猜你到底想投哪一类。

[语言风格]
这份简历现在最像“做了很多事的人写给熟悉内部背景的人看”，不像“写给外部招聘方做快速决策”的文案。要改成更像 benchmark 的写法：少术语挂牌，多因果闭环；少“参与/支撑”，多“定义/构建/验证/优化”；少堆系统名词，多写不可替代的判断和结果。

[最大盲区]
最大的盲区，是把“有闭环经历”误当成“已经证明自己具备闭环 owner 能力”。外部招聘不是听你说链路完整，而是看你有没有把每一段链路的判断权和方法论写出来。没有这个，别人会默认你是强执行，不会默认你是强定义。

[过度采用的风险]
如果一直按现在这个写法投，你最容易卡在一种很尴尬的位置：懂业务的人觉得你算法味不够，懂算法的人觉得你评测方法不够硬，招应用的人又会担心你是不是太想往研究侧靠。结果不是没人要，而是只能拿到“可面可不面”的边缘通过率，进不了最想去的核心面试池。

[签名句]
你以为这份简历已经能证明“我做过 LLM 评测闭环”，出去一看才知道，它目前更像“我参与过闭环”，离“我是闭环里最关键的那个人”还差一层证据。
```
