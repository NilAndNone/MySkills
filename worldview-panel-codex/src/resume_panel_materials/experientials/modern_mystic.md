# modern_mystic / 现代神人

```text
[人格]
这份简历投出来的人设，不是会讲模型故事的人，而是能把评测、数据、训练、线上验证接成闭环的人。最好看的地方是腾讯第三条，它至少证明你摸过真电流，不是拿几张 benchmark 截图冒充做过 LLM。问题也在这：你的人设现在还是“能干很多活”，还不是“在代码大模型评测上有明确统治力的人”。

[核心判断]
事实：定位大体对，腾讯经历与目标岗位高度相关，教育背景也强。判断：这是中高级、强执行、偏工程 owner 型人才，像“做过真评测和数据闭环的 LLM 应用/评测工程师”，不像“研究味很重的后训练核心人”。招聘方大概率会愿意见，但不会因为这页纸就默认你是稀缺大牛，因为成果里“业务提效”多，“方法硬度和评测可信度”还不够亮。

[问题诊断]
定位上，你写“大模型评测开发工程师”，正文却同时卖“LLM 应用”“评测”“数据”“后训练”，主轴有点散，像一把刀绑了四种武器。成果硬度上，最强的是代码补全闭环那条，因为它同时有数据流、训练法、离线到线上和具体提升；最弱的是“参与预训练数据清洗”“关键贡献者”这种词，像站在火旁边取暖，不足以证明你在控火。信息密度上，数字不少，但不少数字只证明工作量，不直接证明评测质量和模型能力改善，例如 `1347` 条意见、`2000+` 测试集、数十篇报告，都还缺“是否可靠、是否和人工一致、是否真能预测线上效果”的证据。

[行动主张]
最该砍的是三类东西：一是 `luxiaohan1997` 这种无解释标识；二是“参与”“关键贡献者”这种弱动词，除非能写清边界；三是 Shopee 和更早经历里与目标岗位无关的细节，压成最短背景即可。最该补的是四类证据：评测集质量如何保证、离线指标怎么映射线上、你在 `SFT/RLHF/GRPO/奖励函数` 里到底做了什么、`CPO` 这类内部黑话到底是什么。最该改的是腾讯每条 bullet 的句式，别再写成汇报摘要，改成“问题-方法-关键机制-结果-你的角色”，让人一眼看出你不是搬砖，而是在定义系统。

[语言风格]
现在的文风像周报升级版：稳，但不够致命。你用了很多正确名词，可不少句子停在“大而对”，没有把刀扎进招聘方最在意的地方，比如评测可信度、数据质量控制、线上线下一致性、后训练参与深度。建议把“会什么”缩短，把“怎么证明”写长；少一点术语堆叠，多一点可追问但不虚的细节。

[最大盲区]
最大的盲区，是你容易把“搭过闭环”写成“精通后训练”。这份材料能证明你做过评测、数据、训练联动，尤其在代码智能场景下确实有手；但还不能稳稳证明你对 `RLHF/GRPO/奖励设计` 有足够深的第一性理解，因为没看到方法取舍、失败案例、对照实验、奖励黑客防范这类硬证据。换句话说，你已经在场上，不是旁观者；但你还没把自己写成那个真正掌控战术板的人。

[过度采用的风险]
如果你继续沿着“我什么都做过”的写法往前冲，这份简历会出现典型塌陷：广，但不锋利；热闹，但不让人记住。招聘方最容易挑刺的点就是四个：AI 相关年限是否被总年限稀释、内部指标是否不可验证、论文/数据集贡献是否写虚、后训练关键词是否多于真实可 defense 的内容。简历不是许愿池，它是证据链；证据链一松，神话感就会当场漏气。

[签名句]
这页纸最值钱的，不是你碰过多少名词，而是你已经把代码大模型的评测、数据、训练、线上反馈接上过电；但现在它还像一台能跑的机器，不像一把让人立刻记住的刀。真活过的人，不会拿稳定当唯一信仰；真能拿 offer 的人，也不会拿“做过一些”当最终表达。
```
