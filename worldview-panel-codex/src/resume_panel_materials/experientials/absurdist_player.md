# absurdist_player / 荒诞游戏派

```text
[人格]
这份简历的人设，不是“会调几个 API 的 LLM 应用仔”，而是“后端底子硬，在代码智能场景里真搭过评测和数据闭环的人”。这比一堆只会写 prompt optimization 的简历有骨头。问题也在这儿：你明明有真活，写法却像技能摊位，什么都摆一点，反而削弱了专业像。

[核心判断]
事实：腾讯这段最有含金量，尤其是代码审查自动化评测、单测生成评测、代码补全从线上数据回流到 SFT+GRPO 再回线上验证，这三条是真证据。判断：你最像“代码智能方向、偏评测/数据闭环的中高级工程型人才”，不像纯研究型，也还没写成“评测体系 owner”。结论：能进面，但现在更像靠谱执行者和子方向负责人候选，不像一眼就能拍板的方法论型选手。

[问题诊断]
定位半清楚半打架：标题写“大模型评测开发工程师”，内容却同时想占评测、应用、后训练三张桌子，招聘方会问你到底是哪一类。成果硬度也不均：`6.25 人日降到接近 0`证明的是自动化提效，不是评测有效性；`34.8%→40.2%`这条最硬，但没写清基线、样本规模、实验周期、归因边界；`1347 条审查意见`和 `2000+ 测试集`有价值，但还不够自动让人闭嘴。最容易被挑刺的还有四个点：`6年半后台与 AI 工程经验`像把传统后台年限一起算进了 AI；`SFT/RLHF/GRPO/奖励函数设计`挂得太满，证据却主要托住一条；`AutoCodeBench（ICLR 2026）关键贡献者`不说清作者位次和具体贡献，就像借论文反光；`参与预训练数据清洗`是典型弱句，既不显能力，还主动邀请追问。信息密度方面，腾讯前三条是金块，Shopee 和鹏城更多是在证明你会做工程，不该和 LLM 主战场平分版面；`luxiaohan1997`和年龄这种信息，从求职收益看就是噪音。

[行动主张]
改法很直接：先定岗，再写证据。投评测岗，标题就改成“代码智能大模型评测/数据闭环工程师”；投应用岗，就写“LLM应用工程师（评测与后训练方向）”，别一行字同时讨好三种岗位。然后把腾讯经历重写成“角色-范围-方法-结果”四连句：你主导了什么，覆盖了哪些语言/仓库/样本，怎么做判分、对齐、误差分析、数据回流，最后指标怎么变。该砍的就砍：年龄、含义不明的 ID、鹏城展开、Shopee 细枝末节、`参与预训练数据清洗`这种弱贡献；该补的就补：人工一致性、线上线下相关性、样本分层、防泄漏、评测指标定义、你在 SFT/GRPO 里到底做到数据策略还是训练策略。别再写`支撑`、`数十篇报告`、`接近0`这类空气词，能量化就量化，不能量化就写机制。

[语言风格]
现在的语言像“我很多地方都沾过”，应该改成“这几件事我真扛过”。招聘语境不吃大词串珠，吃的是硬句闭合：`我主导/搭建了什么`，`规模多大`，`关键方法是什么`，`结果如何`。高危词是`参与`、`支撑`、`关键贡献者`、`接近0`，这些词的潜台词都是“也许有你，但没你也行”；对想冲评测岗的人来说，这种暧昧是主动给自己降级。

[最大盲区]
你以为自己在卖“闭环能力”，招聘方看到的却可能是“参与感很强的多面手”。这份简历最大的问题不是没货，而是没有把“谁定义标准、谁做关键判断、谁对结果负责”钉死。评测岗最看重的不是你见过多少链路，而是你有没有建立过可信链路；这层 owner 感不写出来，功劳就会自动蒸发到团队背景里。

[过度采用的风险]
也别因为这一轮批判就把自己硬改成“后训练算法专家”或者“评测科学家”。你真正值钱的是工程闭环、代码智能场景理解、把数据和评测做成能驱动模型迭代的能力，不是装成基础模型研究员。改过头，简历会从“真干过”变成“术语 cosplay”；面试官一深挖，舞台灯就会全部照在破绽上。

[签名句]
这份简历不是没东西，是把硬货摆成了杂货铺；把“我参与过很多”改成“这条闭环我扛过”，它才像你想应聘的那个人。
```
