# humanist_therapist / 人本关怀派

```text
[人格]
这份简历最像一种人：活是真干了，而且多半干的是别人嫌脏嫌碎、但对模型落地最关键的闭环活；问题不是没东西，而是不会把“做过”包装成“不可误判地证明我做成过”。很多人不是没道理，是没被好好承接过；这份简历则相反，是经历有道理，但表达没把招聘方最在意的证据承接住。

[核心判断]
尖锐一点说：这不是一份“水简历”，但也还不是一份“看到就想约面”的顶级 LLM 评测简历。它强在应用闭环真实、指标有几处能打、代码智能场景足够聚焦；它弱在“评测方法论”和“后训练闭环 ownership”的证据链还不够硬，导致定位卡在“做过很多相关事的应用工程师”而不是“评测/数据/后训练一体化 owner”。最像的层次是中高级偏强执行、偏落地的 LLM 应用/评测工程师，不像研究 scientist，也还没完全站稳平台级负责人。

[问题诊断]
定位上，标题写“大模型评测开发工程师”，但正文最亮的成绩其实是“代码智能场景中的评测+数据+训练+线上验证闭环”。也就是说，你真实卖点比标题更窄、更深，结果标题反而显得泛。招聘方会挑刺：你到底是评测工程师、应用工程师、还是后训练工程师？你都沾，但没有一句话把主轴钉死。  
成果上，腾讯三四条里最能打的是代码补全闭环那条，因为它终于形成了“线上数据 -> 训练/评测数据 -> SFT+GRPO -> 离线评测 -> 线上验证 -> 指标提升”的证据链，这条最像真做过 LLM 迭代的人。其他几条虽然有规模数字，但更像“做了评测工具/数据工程”，还没充分证明“评测标准如何设计、和真实用户价值如何对齐、如何影响模型决策”。招聘方最容易质疑的是：1347 条审查意见、2000+ 测试集、上万条样本，这些量不算小，但还不够自动证明“评测科学、数据高质、结论可靠”。  
信息密度上，优点是没有空话太多；缺点是强弱信息混堆。数学竞赛国奖、专业第一奖学金当然说明脑子不差，但放在这类岗位里只是“底子不错”，不是成交点。Shopee 和鹏城实验室经历也不是没用，但现在占据的叙事权重如果过高，会把你从“LLM 闭环工程师”拉回“后端转 AI 的人”。简历最大噪音不是内容假，而是旧能力还在抢版面。

[行动主张]
改法不要靠“润色”，要靠重组证据链。第一，标题改得更像你真的卖的东西，比如“大模型评测与后训练工程师（代码智能）”或“LLM 评测/数据闭环工程师”。第二，开头自述别写泛泛的“6年半后台与 AI 工程经验”，改成一句带交易价值的话：我在代码智能场景负责评测体系、评测数据构建、后训练迭代与线上验证，做过从评测基准到采纳率提升的闭环。  
第三，把腾讯的四条改成“问题-动作-指标-你的角色”结构。尤其是代码补全那条，要明确你负责了什么核心设计，不然容易像“团队一起做的，你写进来了”。第四，补足评测方法的硬信息：评测维度、标注标准、误差归因框架、离线指标与线上指标如何对齐、样本污染/泄漏怎么控制。你现在写的是“有评测”，还没写成“我知道怎么让评测可信”。第五，砍掉或压缩噪音：`luxiaohan1997` 这种含义不明的 ID，如果不是 GitHub/技术品牌资产，就像在简历上挂了一块没人懂的牌子；Shopee 和鹏城经历每段留 1-2 条最硬结果就够，不要让前朝履历稀释现在的求职主题。第六，论文/数据集那条要写清“关键贡献者”具体贡献，不然就是最容易被面试官追着打的点。

[语言风格]
现在的语言有工程味，但还不够“招聘友好”。你在写“我参与了很多正确的事”，不是在写“我能为你们的模型质量和业务指标负责”。建议整体语气更像提交结案报告，而不是项目纪要：少一些名词堆叠，多一些因果闭环；少一些“参与/支撑”，多一些“设计/主导/落地/提升”。毒一点说，简历不是工作日志，招聘方也没义务帮你脑补贡献。

[最大盲区]
最大的盲区不是技术，而是“证据标准”。你已经在用评测的脑子做工作，却没有用评测的标准写自己。一个做 LLM 评测的人，简历本身却没有把“评测是否可信、数据是否高质、收益是否可归因、角色是否可确认”讲清楚，这会很讽刺。招聘方一旦卡这一点，就会把你从“闭环 owner”降格看成“靠谱执行者”。

[过度采用的风险]
如果你接下来只沿着这份简历的写法继续加料，风险是越写越像“什么都做过一点的泛 AI 工程师”。长期这样，会让你的边界变糊：明明最值钱的是代码智能里的评测与后训练闭环，最后却被看成“能搭框架、会清数据、懂一点训练、也能做后端”的杂糅型人才。杂糅不是原罪，但在竞争岗位里，杂糅如果没有主轴，通常就等于不可替代性不够。

[签名句]
这份简历不是没货，是货压在仓库里没上货架；真正该卖的，是你把 LLM 评测、数据构建、后训练和线上验证串成闭环的能力，而不是让招聘方自己在一堆相关经历里猜你到底能打哪一仗。
```
