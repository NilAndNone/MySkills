# network_jester / 网络乐子人

```text
[人格]
这份简历投出来的人设，不是“算法论文仙人”，也不是“调 API 的应用仔”，而是代码智能场景里能把评测、数据、上线反馈拧成一根绳的工程型选手。最值钱的气质是肯做脏活、能把流程做成指标；最危险的气质是啥都写了一嘴，像在给自己开全能滤镜。

[核心判断]
事实层面，腾讯部分和目标岗高度相关，而且确实有几条硬结果：评测框架、数据构建、闭环优化、线上指标提升。判断层面，这份简历能投“大模型评测开发工程师/偏代码智能的 LLM 应用工程师”，最像高级工程师到资深工程师边缘的工程闭环型人才；但还不像能独立定义通用后训练路线、评测平台规范和研究方法论的人。最强的是“把事情跑通并拿到业务指标”，不是“证明自己在算法层面不可替代”。

[问题诊断]
定位是七成清楚、三成乱炖：标题写评测，岗位写应用，技能又塞进 `SFT/RLHF/GRPO/奖励函数`，很容易让招聘方问一句“你到底主打哪张牌”。腾讯第 3 条代码补全闭环是全简历最硬的一条，因为它真的出现了“线上数据→训练/评测数据→SFT+GRPO→离线评测→线上验证”的链路；但证据链还没封口，缺离线指标、对齐方式、对照组和你本人 ownership 的写法。代码审查评测框架那条次强，价值在于方法和降本；单测 Agent 那条只有规模，没有质量指标，容易被问成“2000+ 测试集然后呢”；日志处理/预训练清洗那条最虚，像陪跑。Shopee 和鹏城能证明工程底盘，但对当前求职方向只是配菜，不该跟腾讯主菜抢镜。`luxiaohan1997` 如果不是明确标注的 GitHub/邮箱前缀，就是纯噪音。

[行动主张]
先做减法，再做举证。第一，标题别写大而空的“大模型评测开发工程师”，改成更贴脸的“代码智能 LLM 评测与闭环优化工程师”，或者直接准备“评测版”和“应用版”两套。第二，把腾讯第 3 条提到第一条，并补全 `CPO` 全称、实验窗口、baseline、离线指标、线上验证口径；这是你最像真懂闭环的证据。第三，给代码审查和单测 Agent 各补一个质量指标，不然现在只是“做了平台”，不是“做成了能力”。第四，`SFT/RLHF/GRPO/奖励函数设计` 不要在技能栏摆满，如果只有一条项目能顶住追问，就收缩成“做过 SFT/GRPO 闭环优化与奖励设计”。第五，`参与预训练数据清洗` 和 `关键贡献者` 这种话要么具体化，要么删，因为它们最容易把面试变成打假现场。第六，教育奖项减脂，只留 HIT 和数学竞赛国家一等奖这两个高信号点；老厂后台经历压缩成底盘说明，不要让一页纸像两份简历缝起来的。

[语言风格]
现在这份文本的语气像“我干了很多硬活，但关键细节你先信我”。这在招聘场里很像节目效果：气势有了，证据密度差半口气。`支撑方案选型`、`参与`、`建设`、`关键贡献者` 这类词都属于简历黑话，面试官一捏就碎。建议把每条改成“对象-方法-规模-结果”四件套，少用抽象动词，多用可盘问但盘不死的指标。

[最大盲区]
最大盲区不是能力本身，而是你没有把“我做过”升级成“我能被验证地证明做过，而且知道为什么有效”。尤其是 LLM 评测/数据/后训练岗位，大家最烦的不是不会吹，而是把团队流水线写成个人全链路英雄传。你现在最容易被挑刺的点，就是 ownership 边界不清、方法细节不清、评测到上线的因果链不清。

[过度采用的风险]
如果继续按现在这个思路往上堆词，你会掉进“全能但不够深”的坑：评测像懂，数据像懂，后训练像懂，应用也像懂，最后像一个什么都能聊十分钟、什么都不一定能扛一个季度的人。反过来，如果因为怕被挑刺把 Shopee/Pengcheng 全砍光，也会丢掉很重要的工程可信度。正确姿势不是把自己包装成研究员，也不是装成纯应用仔，而是把结论收束成一句话：你是有工程底盘、能把代码智能场景的评测和优化闭环跑起来的人。

[签名句]
这份简历不是没货，是把真金、边角料和烟雾弹一起端上来了；先别演“全链路大神”，先把那条最硬的闭环写到谁看都知道是你拽动的。
```
