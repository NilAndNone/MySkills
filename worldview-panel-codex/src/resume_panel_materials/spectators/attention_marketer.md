# attention_marketer / 营销号

```text
[人格]
这份简历的人设不差：不是“会调几个 Prompt 就自称 LLM 专家”的轻飘型选手，而是有后端底子、真进过代码智能场景、也确实摸过评测和数据闭环的人。问题是，人设还没封神，像“从强后台工程师成功切进 LLM 应用/评测”的故事，不像“已经在 LLM 评测体系里站稳山头的 owner”。

[核心判断]
强，在于它终于拿出了几条像样的硬货：自动化评测框架、沙箱执行、日志挖掘、线上到训练再到离线和线上验证的闭环，还有能写进简历的指标提升。这比一堆“参与大模型项目落地”“负责 Agent 能力建设”的空气简历强太多。  
弱，也非常明显：标题叫“大模型评测开发工程师”，但简历主体却像“代码智能方向的应用/平台/数据混合工程师”。你不是没做评测，而是“评测专家画像”还没立住，招聘方很容易问一句：你到底是评测体系 owner，还是把评测当成支撑模型迭代的一环在做？这一问，如果答虚了，整份简历就会从“对口”掉成“沾边”。

[问题诊断]
第一刀，定位有点散。你写了评测、数据、后训练、日志、预训练清洗、Agent、代码补全、后台基建，像什么都做过，但“我最值钱的那个点”没有被钉死。对 LLM 评测岗来说，最值钱的是“定义问题、构造评测、建立指标、验证相关性、驱动迭代”，不是“我也懂一点 SFT/RLHF/GRPO”。后者写多了，反而像在抢算法工程师的人设，最后两边都不够纯。  
第二刀，成果有数字，但还不够“评测味”。“1347 条审查意见、2000+ 测试集、百万日志、上万高质量样本”这些是量，不是证明。招聘方真正想看的是：数据怎么分层、标签怎么定义、评测指标和线上指标相关性多高、误差分析怎么反推数据与奖励函数、baseline 是谁、你的方案为什么可信。现在是“我干了很多”，但还差“所以我真的懂评测科学”。  
第三刀，最像的层次是中高级应用/评测工程师，不像研究型或体系型 leader。更具体点说：像一个能把代码智能业务里的评测、数据、实验链路推起来的人；不像一个一出手就能定义公司级通用评测标准、统一方法学、带团队打平台战的人。这个层次不低，但别装成更高那档，否则面试官会狠狠干你方法论。  
第四刀，Shopee 和鹏城经历在这份目标岗位里噪音偏大。它们证明你工程底子扎实，但对“LLM 评测开发工程师”这个标题的直接支撑有限。尤其 Shopee 那段，写得像经典后端优化业绩，放在这里有用，但太长就像在说：我过去更像后端，不像 LLM。  
第五刀，`AutoCodeBench（ICLR 2026）评测数据集关键贡献者` 这句危险。不是不能写，而是“关键贡献者”这四个字非常虚；“ICLR 2026”如果不写清楚状态，容易被看成借学术名头抬咖位。招聘方会追问：你具体负责什么、第一作者是谁、你的贡献可替代吗、论文和你当前工作能力的关系是什么。

[行动主张]
先砍。砍掉会分散火力的技能堆砌，尤其是没有证据承接的 `SFT/RLHF/GRPO/奖励函数设计` 大词连发；除非每个词后面都有可追问也站得住的项目细节，不然这就是给面试官递刀。Shopee 和鹏城只保留最能证明工程质量和数据系统能力的 1-2 条，别让旧时代后台经历抢戏。  
再补。补最关键的“评测证据链”：评测对象是什么、任务定义是什么、样本怎么来、标注或判定规则是什么、自动化指标是什么、与线上业务指标如何对齐、误差分析发现了什么模式、这些发现如何反馈到数据和后训练。你现在有闭环，但没把闭环讲成方法论。  
再改。标题如果投“LLM 应用工程师”，这份简历已经够能打；如果死投“LLM 评测开发工程师”，就要把腾讯经历重写成“评测体系 owner 叙事”。建议按这个顺序重排腾讯内容：`评测体系搭建 -> 数据构建与误差分析 -> 训练/奖励/对齐闭环 -> 线上效果提升`。让招聘方先信你会评，再信你会调。不是先炫技，再让别人猜你会不会评。  
最后，把每条成果改成“动作+方法+结果+业务意义”。比如不要只写“1347 条审查意见，评测人力接近 0”，而要写成“构建覆盖 5 语言的代码审查自动化评测框架，定义样本与判定标准，沉淀 1347 条高质量审查样本，将单次评测从 6.25 人日压缩至接近 0，并持续支撑方案选型和版本迭代”。同样的事实，信服力差一个量级。

[语言风格]
这份简历现在的语言风格是“我做了很多事”，但目标岗位需要的是“我定义了问题，并且拿方法把问题打穿”。前者是执行者简历，后者才是 owner 简历。你现在最该做的不是继续堆名词，而是把每个成果句都改得更像证词，少一点履历腔，多一点结案报告味。

[最大盲区]
最大盲区不是技术，而是自我包装的主轴不够狠。你明明最有价值的点，是“代码智能场景下的评测-数据-后训练-线上验证闭环实践”，结果你把自己包装成了一个什么都懂一点的人。互联网招聘最怕这种味道：看着很全，细问就散。你这不是能力不够，是卖点没有被收束成一个能一眼成交的标签。

[过度采用的风险]
如果继续沿用这种“什么都写、都沾一点”的写法，风险很直接：投应用岗，别人觉得你评测表述太重；投评测岗，别人觉得你方法论不够硬；投后训练岗，别人又会觉得你训练深度不够。最后变成一份人人看得懂、但没人觉得非你不可的简历。信息密度高，不等于转化率高；没有主轴的高密度，只是高级噪音。

[签名句]
这份简历最尴尬的地方，不是不强，而是强点很多、爆点不够集中。它最像“已经摸到 LLM 评测门槛以上的强执行型工程师”，还没完全长成“让招聘经理一眼认定你就是评测 owner”的人。你这不是简历问题，你这是一个典型的包装失焦案例。
```
