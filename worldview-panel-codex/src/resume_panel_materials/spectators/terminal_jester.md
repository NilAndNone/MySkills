# terminal_jester / 终极乐子人

```text
[人格]
这份简历透出来的人设，不是会讲模型段子的人，是在代码智能场里真干过脏活的人。好处是有地气，坏处是有点贪，一页纸想同时证明自己会评测、会数据、会后训练、会应用落地，像把四碗菜扣进一个饭盒，量挺足，卖相有点乱。

[核心判断]
强在最近这段腾讯经历是真有货，尤其“线上数据→训练/评测数据→SFT+GRPO→离线评测→线上验证→指标提升”这条，算是能证明你不是只会喊黑话。弱在定位没钉死，很多表述还停在“参与过、支撑过、关键贡献者”这种半硬不硬的层面。最像的人才层次，是中高阶、强工程落地的代码智能 LLM 选手，能独立扛评测/数据/迭代闭环子模块；不像研究型 benchmark 主导者，也不像一眼拍板的算法 owner。

[问题诊断]
最大的问题不是没干货，是货架太乱。标题写“大模型评测开发工程师”，经历里是“LLM应用工程师”，技能又往“SFT/RLHF/GRPO/奖励函数”伸，像三份简历拼成一份。招聘方最容易挑刺的点也很集中：一是“6年半后台与AI工程经验”有点滑，前半段更像后端，不像AI；二是评测成果写了规模，没写足严谨性，比如评测标准、和人工判断的一致性、误差分析怎么做；三是闭环写出来了，但你的所有权边界不够清楚，尤其 GRPO、奖励函数到底你主导到什么程度；四是“关键贡献者”“参与预训练数据清洗”这种词太像往自己脸上贴金，证据味不够；五是 `luxiaohan1997` 含义不明，纯噪音，像简历上掉了个螺丝。

[行动主张]
最该改的不是加词，是减法加钉子。第一，做双版本，评测岗就把主线钉成“代码智能评测体系+数据构建+离线/线上对齐”，应用岗就钉成“代码智能能力建设+闭环优化+线上指标提升”，别一份简历同时讨好三类岗。第二，自述重写，别把后端年限和AI年限混着卖，老老实实分开。第三，腾讯经历按“场景、动作、你的所有权、验证方法、结果”重写，少写“支撑”“参与”，多写“负责/主导了什么，怎么验证有效”。第四，最该补的是评测严谨性证据：标注规则、judge 方案、离线与线上相关性、误差分类、sandbox 约束；没有这些，评测岗会觉得你在跑脚本，不是在做 benchmark。第五，最该砍的是噪音：旧后端经历压缩成工程底座，`luxiaohan1997` 不解释就删，“参与预训练数据清洗”说不清就别写。

[语言风格]
现在这份文本像“关键词大集市”：术语多、动作多、规模多，但不少句子像项目汇报旁白，不像法庭证词。改法很简单，少一点“我接触过什么”，多一点“我定义了什么、验证了什么、把什么指标打到了哪里”。简历最好像审讯笔录，不要像主持人串场稿。

[最大盲区]
最大盲区是把“我确实做过闭环”误当成“简历已经充分证明我是闭环 owner”。这中间差着一条证据链。你现在更像做过很多关键活的人，但还没把“哪部分是我单扛、哪部分是我定义标准、哪部分是我拍板结果”写到让人闭嘴。

[过度采用的风险]
如果继续维持这种“什么都写一点、每样都蹭点高级词”的路子，评测岗会嫌你不够严谨，应用岗会嫌你业务故事不够完整，后训练岗会嫌你算法深度不够。最后最常见的死法不是被立刻拒，而是被放进“再看看”那摞。那摞说白了，就是人才垃圾中转站。

[签名句]
这简历不是没干活，是干了不少活，却老想一页纸把评测、应用、后训练三个人设一起演完。最该改的不是再堆术语，是把“我到底靠什么吃这碗 LLM 饭”钉死；不然就只能当“做过一点大模型的强后端”，受着。
```
