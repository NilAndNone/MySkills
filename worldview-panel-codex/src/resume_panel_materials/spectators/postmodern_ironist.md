# postmodern_ironist / 后现代解构派

```text
[人格]
先拆叙事再看证据。这份简历的问题不是“没做事”，而是太想把评测、数据、后训练、应用四张牌一起打。你显然不是那种只会写 prompt 的转行选手，但现在这套写法在偷吃“关键词齐全”的红利，一旦面试官认真追问，第一反应就会变成：你到底真正 owner 了哪一段？

[核心判断]
强项很明确：腾讯这段不是空心 AI 经验，而是落在代码智能场景里的真实链路，尤其“代码补全闭环”这条最硬，因为它同时出现了线上数据、训练/评测数据、SFT+GRPO、离线评测、线上验证和业务指标提升；这说明你至少做过一条能落地、能归因、能看线上结果的链路。教育背景也强，能证明底子和学习能力。弱项也很明确：整体更像“中高级、偏落地的 LLM 应用/评测工程师”，像一个能把局部闭环跑起来的模块 owner，不像一个已经坐实“评测体系 owner / 后训练核心 owner / 通用 benchmark 设计者”的人。

[问题诊断]
最容易被挑刺的点有四个。第一，定位发虚：标题写“大模型评测开发工程师”，岗位写“LLM应用工程师”，技能又塞进 SFT、RLHF、GRPO、奖励函数、预训练清洗，像在对所有 JD 同时示好。第二，成果硬度不均：代码补全那条是硬货，代码审查评测和单测 Agent 评测更多是在证明你搭了框架、做了测试集，但没直接证明模型质量提升、评测有效性、离线线上相关性；`6.25 人日降到接近 0` 是工程效率，不是模型能力。第三，很多数字只有量，没有方法学：`1347条审查意见`、`2000+测试集`、`上万条高质量样本`、`百万日志` 都会被问覆盖度、抽样策略、标注一致性、误差归因和数据污染控制。第四，噪音比偏高：`luxiaohan1997` 是无意义噪音；Shopee 和鹏城经历不是不能留，但现在更像“证明一直有工作”，没有被翻译成对 LLM 岗位的迁移价值。

[行动主张]
砍：删掉 `luxiaohan1997` 这种不提供职业判断的信息；把 Shopee、鹏城各压到 1-2 行，只保留高并发、大规模数据、工程化这些能给当前岗位背书的点；“参与预训练数据清洗”如果拿不出具体职责，就别写得像核心贡献。补：给最硬的 2-3 个项目补责任边界和方法细节，尤其是评测集怎么构、样本怎么筛、judge/规则怎么定、误差怎么分析、离线指标怎么对应线上指标、你控制了哪些变量。改：把主线收成一句话，例如“代码智能方向 LLM 评测与数据闭环工程师”，然后把“代码补全闭环”提到第一条，把它写成全简历的证据中轴；`CPO +30%` 这种黑话要解释，`34.8%→40.2%` 要补时间窗和样本规模。别再试图一份简历同时证明你是评测专家、应用专家、后训练专家、数据专家，外部招聘不吃这一套。

[语言风格]
现在这份文本很像把大厂内部晋升材料切了一页出来：术语密、数字多、结论先行、边界后置。圈内人一眼能看出你做过事，但也会一眼看出你在用“黑话浓度”掩盖“ownership 边界不够清楚”。对内汇报可以这样写，对外求职不行；外部招聘要的是可核验，不是术语对齐。

[最大盲区]
最大的盲区，是默认“写了 SFT/RLHF/GRPO/奖励函数/评测集/预训练清洗”这些词，别人就会自动脑补你做过完整闭环。不会。招聘方真正看的只有两件事：你定义了什么机制，你拿到了什么可归因结果。名词不是证据，责任边界和验证链条才是证据。

[过度采用的风险]
如果继续沿着现在这套写法加词堆料，这份简历会把一个本来有真实工程战绩的人，写成“LLM 热词批发商”。最糟的不是被当成菜，而是被当成滑：什么都沾，什么都像参与过，偏偏最值钱的 ownership 讲不硬。那时候你失去的不是一个面试机会，而是简历信用。

[签名句]
先别问这份简历厉不厉害，先问它有没有把最值钱的证据放在最前面。现在的问题不是没货，而是真货和话术混着卖，最后把“做过闭环的人”写成了“会描述闭环的人”。
```
