# cynical_detached / 犬儒抽离派

```text
[人格]
按招聘方最不愿上头的视角看，这份简历像一个做过真活的人，不是 PPT 型，也不是只会调 API 的“LLM 应用工程师”。但它同时有个老毛病：怕自己不够全，于是把评测、数据、后训练、工程底座全往上挂，像在说“我都沾过”，而不是“这块我能扛”。

[核心判断]
事实：定位大体清楚，主轴是代码智能场景下的 LLM 评测、数据构建、能力验证，腾讯经历也基本对得上。判断：最像中高级、偏工程落地的代码智能/评测闭环选手，能搭评测体系、能做数据、能推一段模型迭代，但不像基础模型核心算法 owner，也不像研究型尖子。对“大模型评测开发工程师/LLM应用工程师”有竞争力；对更偏后训练核心岗，证据还不够硬。

[问题诊断]
事实：最硬的东西都在腾讯，且有数字，5 语言、1347 条审查意见、6.25 人日趋近 0、2000+ 测试集、采纳率 34.8% 到 40.2%、CPO +30%、百万日志、上万样本。判断：这些数字说明你做过体系和闭环，但还没把“我主导过”钉死。1347 条审查意见不算特别大盘子，2000+ 测试集没说明区分度和质量，`数十篇报告` 不算成果只算过程痕迹，`CPO` 未定义，采纳率也没给时间窗、样本量、统计口径。最容易被挑刺的点就一句：你看起来参与过 LLM 评测/数据/后训练闭环，但简历还没证明你是哪一环的 owner。

[行动主张]
先砍：`luxiaohan1997` 这种意义不明的信息，`数十篇报告` 这种过程型表述，Shopee/鹏城里和目标岗位关系弱的细节，技能区报菜名式堆词。再补：每条腾讯经历都补齐“我负责什么、规模多大、指标怎么定义、和 baseline 比赢在哪、最后线上怎么验”，尤其是代码补全闭环那条，要把“线上数据→训练/评测数据→SFT+GRPO→离线评测→线上验证”拆成能经得住追问的证据链。再改：技能改成三块，“评测体系/数据构建/后训练协同”；如果后训练不是主导，就写“参与 SFT/GRPO 数据与奖励设计”，别硬写成训练 owner。

[语言风格]
现在的文本气质是“关键词很全，像懂很多”，但招聘方看多了，默认先打折。更有效的写法是少喊概念，多交代约束和结果。别写“能力建设/能力验证”这种空话，改成“为代码审查/单测生成建立自动化评测集与执行框架，支撑版本选型与模型迭代”。别写“参与预训练数据清洗”，要写清处理的是什么脏数据、规模多大、清洗规则是什么、对下游有什么影响。简历不是摘要，别指望读者替你补全贡献。

[最大盲区]
最大盲区是把“我串过整条链路”误当成“别人会默认我能 owning 整条链路”。不会。招聘方的默认心态更冷：没写清 ownership，就按参与算；没写清指标定义，就按口径可疑算；把 `SFT/RLHF/GRPO` 一股脑写上去，就按关键词防御性堆叠算。另一个盲区是旧后端经历写太细，容易把“我现在是 LLM 评测/应用方向”冲淡成“我只是一个转向中的后端”。

[过度采用的风险]
如果继续维持这种“每个关键词都想沾一点”的写法，风险不是显得全面，风险是显得不敢下注，最后谁都不像。反过来，如果为了显得硬，把自己往后训练算法位上抬太高，也有副作用：筛选时也许加分，面试时会被 reward 设计、数据配比、ablation、offline-online correlation 这些问题狠狠干穿。简历最怕的不是保守，是虚胖。

[签名句]
这份简历不是没货，是货摆得太杂；像做过闭环的人，写出来却像一个不肯放弃任何关键词的人。
```
