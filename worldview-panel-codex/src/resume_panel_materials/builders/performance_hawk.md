# performance_hawk / 绩效鹰派

```text
[人格]
这份简历传出来的不是“会调包的 LLM 应用仔”，而是“偏评测与数据闭环的工程型选手”。好处是方向比一般“做过一点 prompt、接过一点模型 API”的人硬得多；坏处是你想吃“大模型评测开发工程师”和“LLM 应用工程师”两张饼，但简历主叙事明显更像前者，后者只是顺带沾边。世界先看你能不能打，再听你委不委屈，这份简历至少在“打过仗”这件事上，比市面上大量空心简历强。

[核心判断]
事实：你最硬的证据是腾讯这段，尤其是“代码补全闭环”和“自动化评测框架”两条，已经能证明你不是只会写 case、跑 benchmark，而是碰过线上数据、训练/评测数据构建、离线评测、线上验证、指标回收这一整条链路。  
判断：这份简历最像“中上水平、偏工程闭环的 LLM 评测/应用交叉型工程师”，不是纯研究型，也不是顶级后训练 scientist，更不是只会业务接 API 的初级应用工程师。  
结论：如果岗位真招“评测开发工程师”，这份简历有面试价值；如果岗位更偏“训练算法/后训练研究员”，它会被追着问细节；如果岗位更偏“通用 LLM 应用产品工程”，它又显得有点窄，过度绑定代码智能场景。

[问题诊断]
第一，定位不够狠。标题写“大模型评测开发工程师”，但经历里又放“LLM应用工程师”，技能还塞 SFT/RLHF/GRPO/奖励函数设计，结果像是在试图证明“我全都懂”。招聘方会理解成一句话：边界不清，怕你什么都沾一点、没有一项穿透。  
第二，成果有硬度，但硬得不够统一。最硬的是采纳率 34.8%→40.2%、CPO +30%，这是真结果。相对之下，“1347条审查意见”“2000+测试集”“数十篇报告”“上万条高质量样本”这些更像工作量，不是价值锚点。量很大，不等于说服力很大。  
第三，你声称做过“LLM 评测/数据/后训练闭环”，但证明链条还差关键钉子。现在只能证明“参与并推动过闭环”，还不足以直接证明你主导过实验设计、指标定义、奖励建模取舍、数据污染控制、线上归因方法。也就是说，做过，但简历没把“你是核心变量”钉死。  
第四，信息密度还行，但噪音比不够低。Shopee 和鹏城实验室那两段证明你有工程底子，这没问题；问题是它们对当前求职目标的支撑力度远低于腾讯，篇幅和注意力如果没压缩，就会稀释主卖点。教育里的竞赛奖项也一样，亮，但不是现在最值钱的筹码。  
第五，最容易被挑刺的点有四个：  
1. “AutoCodeBench（ICLR 2026）关键贡献者”很危险。关键贡献者不是作者位，不说清楚贡献边界，容易被当成借光。  
2. “参与预训练数据清洗”太虚。参与两个字在简历里几乎等于没有 ownership。  
3. “luxiaohan1997 含义不明”这种信息如果真出现在显眼位置，只会制造噪音。  
4. 技能栈太满，像在求覆盖率，不像在做排序。招聘看简历不是看你会多少名词，是看你哪三样最能变现。

[行动主张]
第一刀，重写标题和摘要，别贪。更合理的定位是：“大模型评测/数据闭环工程师（代码智能方向）”或“代码智能 LLM 评测与应用工程师”。先把你最能打的战场钉死。  
第二刀，把腾讯经历改成“闭环证据链”写法，不要按杂项堆。建议优先顺序：  
1. 代码补全闭环：突出你定义了什么目标、设计了什么奖励/数据策略、最后把什么线上指标打上去。  
2. 自动化评测框架：突出评测维度、覆盖语言/仓库、如何替代人工、如何支撑模型选型。  
3. 样本构建与日志挖掘：突出样本来源、筛选标准、质量控制、对训练或评测的实际贡献。  
第三刀，砍虚词。把“参与预训练数据清洗”改成可验证动作；如果说不出动作，就删。把“数十篇报告”删成一句“支撑 X 次方案选型/迭代决策”；报告不是成果，决策影响才是。  
第四刀，补关键细节。你现在最该补的不是更多名词，而是每条成果中的方法论钉子：  
1. 评测指标定义了什么，为什么这样定义。  
2. 数据集如何避免泄漏、偏差、脏样本。  
3. 离线指标如何和线上指标对齐，相关性怎样。  
4. 奖励函数大致优化什么目标，怎么防 reward hacking。  
第五刀，旧经历瘦身。Shopee 保留 1-2 条最硬的系统级成果即可，证明你不是只会 LLM 的纸上工程师；鹏城实验室再压缩，只留“数据接入/归档/容器化”的骨架。你现在不是在投“资深后端工程师”。

[语言风格]
这份简历最好的地方，是没有掉进“AI 项目经验 = prompt 调优 + 接口封装 + demo 落地”的低级坑。你至少拿出了自动化评测、数据构建、离在线闭环、线上指标提升这些真钱。  
但问题也正出在这里：你已经摸到门了，却还没把门牌号写清楚。现在的写法像是在说“我既懂评测、也懂数据、也懂后训练、也懂应用”。招聘方的翻译版本是：“你到底哪块最值钱？”简历不是年终述职，不需要面面俱到，需要让人 10 秒内知道你排位赛打哪一路、赢过哪些局。

[最大盲区]
你这份简历最大的盲区，不是能力不够，是“把做过很多事”误当成“证明自己不可替代”。事实是，招聘方会优先判断你是不是闭环中的核心杠杆，而不是勤奋参与者。现在材料能证明你干了不少活，但对“你定义问题、你设计方法、你推动指标、你承担归因”的 ownership 还不够狠。缺的不是经历，是归属权表达。

[过度采用的风险]
如果你按“绩效鹰派”思路把这份简历继续往死里压，会有一个副作用：它会变得非常能打，但也会更窄。你会更适合“代码智能/评测体系/数据闭环”类岗位，却可能牺牲一部分“通用 LLM 应用工程师”的兼容性。这个代价值不值得，看你的投递池子。如果目标岗位本来就偏评测与代码智能，那就该窄，别装宽。

[签名句]
这份简历不是弱，问题是还不够锋利：你已经证明自己上过场，但还没把“我是这条闭环里最难替代的那个人”写到招聘方没法装看不见。
```
