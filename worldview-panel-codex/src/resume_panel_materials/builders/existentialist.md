# existentialist / 存在主义者

```text
[人格]
只按招聘经理/TL 的冷读法看这份文本，不替你脑补版式，也不替你补证据。标准只有一个：这份简历能不能在 30 秒内让人相信，你真做过 `LLM评测-数据-后训练-上线验证` 闭环，而不是在旁边围观过。

[核心判断]
这不是一份差简历，甚至比一堆“只会接 API、写点 Prompt”的 LLM 应用工程师强一截；但它也没强到“评测/后训练 owner”那档。它最像的人才层次是：代码智能场景里偏强的工程型核心 IC，长于把评测自动化、数据构建、实验迭代和线上收益串起来；不像研究型算法，也不像能独立定义通用大模型评测体系的人。强项是真的有，问题是证据没有收束成一个足够锋利的身份。

[问题诊断]
定位上，标题写“大模型评测开发工程师”，正文最强叙事其实是“代码智能方向的 LLM 应用 + 评测 + 后训练闭环”，范围更窄也更值钱。最硬的一条是 `线上数据→训练/评测数据→SFT+GRPO→离线评测→线上验证`，而且给了 `34.8%→40.2%`，这条是真金白银，说明你不是只会搭台子。问题在于，除了这条，其他很多内容还是“规模指标”和“勤奋指标”：`5语言`、`1347条审查意见`、`2000+测试集`、`数十篇报告`、`百万日志`。这些能证明你做了不少事，但不能自动证明你做得深。招聘方最容易挑刺的点有六个：`RLHF` 写进技能但正文没撑住；`CPO`、`接近0` 这种内部/模糊表述对外不友好；`关键贡献者` 没讲清边界；`参与预训练数据清洗` 像顺手挂件；`6年半后台与 AI 工程经验` 容易被追问 AI 经验到底几年；Shopee/鹏城这两段对目标岗位的噪音比偏高。

[行动主张]
第一，把身份钉死成一句话，比如 `代码智能方向 LLM评测/应用工程师` 或 `LLM评测与后训练工程师（代码智能）`，别一边想投评测、一边想投应用、再顺手把后台也背在身上。第二，把腾讯第 3 条闭环成果提到第一条，按 `场景-职责-方法-结果` 重写；没有明确 ownership 的地方，少用“参与”“支撑”。第三，技能区砍掉关键词通胀：没有硬证据就别把 `RLHF` 和 `预训练数据清洗` 摆成核心卖点；传统后端栈压成一行就够。第四，补“评测岗门票级”信息：评测维度怎么定义、离线怎么和人工/线上对齐、沙箱执行如何控误差、bad case 如何回流数据和训练。第五，压缩 Shopee 和鹏城，把空间让给腾讯和 `AutoCodeBench`；`AutoCodeBench` 也别只写“关键贡献者”，要写清你具体负责了什么。第六，删掉年龄和不明所以的 `luxiaohan1997`，所有缩写第一次出现都展开。

[语言风格]
现在的语言像内部述职，不像对外求职。你用了不少“支撑”“参与”“关键贡献者”“高质量”“接近 0”这种自证词，这类词最大的作用是提醒别人来盘你。招聘方不吃形容词，只吃边界和证据。把“我很重要”改成“我负责 A，用 B 方法，把 C 指标从 D 做到 E”；把“报告很多”改成“评测如何影响选型/迭代”；把“高质量样本”改成“筛选规则、有效率、抽检或线上相关性”。

[最大盲区]
这份简历最大的盲区，是把“接触面很广”误当成“证明力很强”。你列出 `SFT/RLHF/GRPO/奖励函数/数据清洗/误差分析`，不等于别人就信你做过闭环；他们只会继续问：哪一段是你 owner，哪一段是你配合，指标为什么可信，失败实验你砍过什么。广度是加分项，模糊会直接把分扣回去。

[过度采用的风险]
如果按这套毒舌改过头，你会把简历改成只剩一条最亮的腾讯项目，反而把自己的工程底盘削没了。正确做法不是把过去删光，而是把非目标经历降维成“工程化地基”，把目标经历抬成“可验证的 LLM 闭环能力”。别为了显得像算法人，把你最值钱的应用落地和线上收益一起删掉。

[签名句]
这份简历已经证明你不是 LLM 热词搬运工，但还没稳到让人一眼认定你是评测闭环的 owner。招聘方不会替你把“我参与过”脑补成“我做成过”；世界不替你写意义，简历也别拿模糊表述给自己逃票。
```
