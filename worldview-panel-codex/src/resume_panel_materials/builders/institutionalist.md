# institutionalist / 制度修补派

```text
[人格]
事实判断：这份简历最有价值的部分，不是“会用多少术语”，而是它确实在腾讯里堆出了一条相对完整的代码智能评测/数据/训练/验证链路。  
价值判断：从制度修补派视角看，这比“我调过几个 prompt、接过几个 Agent”高级一截，因为它开始像一个能把能力建设沉淀成流程的人。  
建议：但简历现在最大的问题，是“想证明自己做过闭环”，结果写法还停留在“项目流水账 + 关键词堆叠”，离“让招聘方放心你能独立搭建评测体系”还差最后一层证据组织。

[核心判断]
事实判断：这不是低端候选人。按材料看，他最像“中上段的业务型 LLM 应用/评测工程师”，强于把代码智能场景里的评测自动化、数据构建、线上反馈、后训练串起来，明显强过只会接 API 和写 Demo 的人。  
价值判断：但也还没稳到“评测负责人/后训练核心 owner”的层次，因为很多成果有数字，没有方法学证明；有闭环名词，没有足够强的归因证据。  
建议：如果投“大模型评测开发工程师”，通过率取决于能不能把自己从“做过相关活的人”改写成“能定义评测标准、生产高质量数据、驱动模型迭代的人”。

[问题诊断]
事实判断：强项有四个。第一，腾讯经历与目标岗位高度对口，这是主干，不是擦边。第二，有几个像样的量化结果：5种语言、1347条审查意见、2000+测试集、百万级日志、上万条样本、采纳率提升，这些至少说明不是空喊。第三，写到了离线/线上对齐、误差分析、奖励函数、SFT+GRPO，这比单纯“调模型”更接近真实工程闭环。第四，早年后端基础不差，能支撑数据链路和系统化落地。  
价值判断：弱项也很集中。第一，定位不够收口。标题写“评测开发”，内容却在“评测/数据/训练/应用”四条线上同时开花，像什么都沾，但没有一句话把自己的主航道钉死。第二，成果硬度参差不齐，很多表述停在“做了框架、产出报告、支撑选型”，这对招聘方来说是过程，不是结果。第三，可信度有几个明显毛刺：`6年半后台与AI工程经验` 很容易被质疑把纯后端年限硬算成 AI；`单次评测人力从6.25人日降到接近0` 太像简历腔，容易招反感；`CPO +30%` 没定义；`参与预训练数据清洗` 贡献边界不清；`关键贡献者` 也不是一个能自动换算成个人技术含金量的说法。第四，Shopee 和鹏城实验室经历有能力证明作用，但对当前岗位的信号密度偏低，篇幅稍不慎就会变成噪音。  
建议：最该补的不是更多名词，而是每个关键成果背后的“评测对象是什么、指标怎么定义、数据怎么来、基线是什么、你具体负责哪一段、结果怎么验证”。

[行动主张]
1. 先重写定位句。别再写泛泛的“6年半后台与AI工程经验”，改成“聚焦代码智能场景的评测体系、评测数据构建与模型迭代验证”，把 AI 年限和后端年限分开写，降低被挑刺概率。  
2. 腾讯每条成果按固定模板重写：`任务对象 + 你的职责 + 方法/机制 + 数据规模 + 指标结果 + 业务用途`。现在缺的是“方法和归因”，不是数字本身。  
3. 把“支撑方案选型和模型迭代”这种空话具体化。比如是支撑了几轮模型对比、淘汰了哪类方案、把人工评审前置成自动过滤、线上回流如何进入训练/评测集。不给细节，这句话等于没写。  
4. 对“代码补全闭环”这条重点加固。这是全简历最像核心竞争力的一条，必须明确：线上日志怎么筛、训练样本怎么构、奖励函数优化什么、离线指标和线上指标怎么对齐、采纳率提升的时间窗和实验口径是什么。  
5. 砍掉或压缩低相关表述。Shopee 和鹏城只保留能证明工程底盘和数据治理能力的两三句，不要让它们和腾讯主线抢版面。  
6. 技能区去泡沫。`SFT、RLHF、GRPO、奖励函数设计、实验设计` 如果没有对应成果锚点，就会像关键词投喂。技能项必须和项目成果一一对上。  
7. 论文/数据集表述要降虚火。`ICLR 2026 论文对应评测数据集关键贡献者` 可以写，但别指望它自己加分很多。招聘方更在意你具体做了哪部分 benchmark 设计、数据质检、评测协议、标注规范。  
8. 补一个“代表性评测能力”小节会更有效。列出你熟悉的评测维度、自动化执行方式、误差分析方法、线上线下对齐经验，比单纯罗列技术栈更像目标岗位。

[语言风格]
事实判断：现在的语言风格偏“广撒术语 + 结果口号”，像在努力证明自己沾过所有热点。  
价值判断：这对初筛可能有用，但对技术面试官和招聘经理不够稳，因为他们会本能地追问定义、口径、归因、贡献边界。  
建议：改成“少一点热词，多一点机制”。少写“参与、支撑、关键贡献”，多写“设计了什么规则、建立了什么链路、定义了什么指标、解决了什么偏差”。

[最大盲区]
事实判断：这份简历最大的盲区，不是能力不够，而是“证据组织落后于实际工作量”。它看起来做了很多，但还没有把“我是真的懂评测闭环”证明到让人懒得质疑。  
价值判断：招聘方最容易下手挑刺的点有四个：AI 年限是否注水；成果是否可归因到本人；指标口径是否经得起问；所谓后训练经验是不是只停留在调参和贴标签。  
建议：面试前也要同步准备口径，尤其是 `6.25人日`、`CPO +30%`、`34.8%→40.2%`、`上万条高质量样本` 这几个数字，必须能当场解释定义、样本范围、对照组和你的责任边界。

[过度采用的风险]
事实判断：如果继续沿用现在这种写法，短期看像“什么都做过”，长期效果是把自己写成了一个配置很多但主核不清的工程师。  
价值判断：对“大模型评测开发工程师”岗位，这种风险很现实，因为这个岗位最怕两类人：只会讲故事的，和什么都懂一点但拿不出评测方法论的。  
建议：不要再继续加新名词、新项目、新 buzzword。最该做的是收缩叙事，把腾讯经历压成一条清晰主线：`评测体系建设 -> 数据构建 -> 后训练验证 -> 线上效果闭环`。你不是缺内容，你是缺编排纪律。

[签名句]
靠情绪点火很容易，靠制度续航才算本事。放到这份简历上就是：别再靠术语和大词点火了，把评测规则、数据机制、验证闭环写扎实，招聘方才会相信你不是蹭到 LLM，而是真的把体系做起来的人。
```
