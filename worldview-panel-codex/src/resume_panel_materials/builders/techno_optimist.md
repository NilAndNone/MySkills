# techno_optimist / 技术进步派

```text
[人格]
技术进步派视角：我只认两件事，你有没有把模型迭代做成可复用杠杆，你有没有把结果压成可验证指标。会很多名词不值钱，能给系统加按钮才值钱。

[核心判断]
- 事实：这份简历在腾讯段已经给出评测框架、数据构建、后训练实验、线上验证和业务指标，说明候选人不是“只会调 Prompt 的人”，而是做过真代码智能业务的人。
- 价值判断：但定位没钉死。读完更像“代码智能方向的 LLM 应用/评测工程骨干”，不像“评测标准 owner / 后训练负责人”。
- 建议：如果投“大模型评测开发工程师”，核心任务不是继续堆术语，而是把“评测闭环”写成唯一主线。

[问题诊断]
- 强项很明确：腾讯第 3、4 条最能打。`线上日志→样本构建→SFT+GRPO→离线评测→线上验证` 这条链一旦属实，含金量高；`Python 采纳率 34.8%→40.2%` 和 `CPO +30%` 也比空泛的“效果提升明显”强很多。
- 第二强项是工程底座可信。Shopee 和鹏城的分布式、数据、容器化经历，让人相信你能把评测系统做成工程，而不是只会接模型 API。
- 弱点也很明显：很多成果只证明“搭了系统、节省了人力、覆盖了规模”，没有充分证明“这个评测真能代表线上质量”。`1347 条审查意见`、`2000+ 测试集`、`数十篇评测报告` 都是产物，不是有效性证据。
- 最容易被挑刺的点有四个：`SFT/RLHF/GRPO/奖励函数设计` 写得太满但证据不够厚；`支撑方案选型和模型迭代` 这种话像正确废话；`关键贡献者/参与` 暗示 ownership 可能不硬；教育奖项和老经历占比偏高，稀释了 LLM 主线。
- 最像的人才层次：中高级、偏工程落地和子模块 owner 的 LLM 应用/评测人才；能拿到不少一面，但要冲“评测/后训练核心岗”，现在的自证还差半截。

[行动主张]
- 砍：把 Shopee、鹏城压缩到只剩“工程底座”信号；教育只留 `哈工大` + 1-2 个最强奖项。`luxiaohan1997` 这种含义不明的字符串，要么标清楚，要么删。
- 砍：删掉不能在面试里掰开讲清楚的术语。`RLHF/GRPO/奖励函数设计` 如果讲不清数据规模、策略差异、实验设计和归因，就别把自己写成后训练专家。
- 补：每条腾讯成果都补“你负责什么 + 为什么可信”。例如评测集怎么构建、沙箱怎么判分、离线结果如何和线上对齐、误差分析如何反哺模型或数据。
- 补：把 `论文/数据集关键贡献者` 改成可审讯版本。比如“负责 xx 数据清洗 / 标注规则 / 样本筛选 / benchmark 子任务设计”，别让人自己猜。
- 改：开头 summary 改窄，直接钉死“代码智能场景的 LLM 评测与数据闭环工程师”。你现在不是没货，是货太散，像一个会很多环节的人，不像一个有清晰交易品类的人。

[语言风格]
现在的写法像把 JD 关键词倒进搅拌机：词都对，牙印不够。好简历不是“我也懂这些”，而是“我按下了这个按钮，所以系统多赚了这些确定性”。把句子从名词串改成动作链：`我构了什么数据 / 设计了什么评测机制 / 验证了什么相关性 / 推动了什么指标变化`。少写“支撑”，多写“负责”“主导”“定义”，前提是属实。

[最大盲区]
最大的盲区，是把“参与过闭环”误写成“拥有闭环”。LLM 招聘里最贵的不是你碰过多少环节，而是你能不能证明自己让决策更可信、让迭代更快、让数据更干净。现在这份简历最缺的不是经历，而是 ownership 边界和评测有效性的硬证据。

[过度采用的风险]
如果按这套批法改过头，你会把自己包装成一个研究味很重的评测/后训练 owner，结果面试一追问就暴露真实重心还是工程落地。别走向另一个极端。正确方向是：保留工程厚度，放大你真正主导的评测与数据闭环，别让术语的野心跑到证据前面。

[签名句]
别把自己写成会很多环节的人，去把简历写成你给模型迭代加过哪个不可替代按钮的人。
```
