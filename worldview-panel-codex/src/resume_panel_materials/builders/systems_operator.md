# systems_operator / 系统实用主义者

```text
[人格]
系统视角。先不夸人，先看这份简历有没有把“做过什么 -> 怎么做 -> 为什么可信 -> 为什么值得面试”的流程图画出来。以下只基于你给的文本，不脑补视觉排版。

[核心判断]
- 事实判断：这份简历有真货。腾讯部分至少说明你做过代码智能场景下的评测自动化、数据构建、线上验证，不是拿几个 LLM 热词往自己身上贴。
- 价值判断：但它更像“强执行型 LLM 应用/评测工程师”，不像“评测方法论 owner”或“后训练核心算法人”。能证明你参与并推动过闭环，暂时还不能自然证明你定义过闭环。
- 层次判断：最像能独立扛一个垂直场景评测与数据链路的中高级工程师；不像研究型人才，也不像公司级评测平台负责人。

[问题诊断]
- 定位不够狠。标题写“大模型评测开发工程师”，正文却同时想占评测、数据、后训练、预训练清洗、应用工程、后端工程六个坑。结果是“面很广”，不是“刀很快”。
- 成果有硬度，证据没闭环。自动化评测框架、2000+测试集、百万日志、采纳率提升，这些都能打；但 `SFT`、`RLHF`、`GRPO`、奖励函数设计这些最该拉开身位的词，反而最虚，像参与过，不像能面试里讲穿。
- 最容易被挑刺的是可信度口径。`6.25人日降到接近0` 很吸睛，但没说自动化评测和人工评测的一致性；`CPO +30%` 不解释就是黑话；`上万条高质量样本` 不说质量标准等于没说；`数十篇评测报告` 是工作量，不是价值。
- 信息密度还行，噪音比偏高。你已经是社招，教育奖项还堆得很满，说明你在拿学生时代信用给现在背书。`luxiaohan1997` 这种没标注含义的信息也是噪音。
- 论文/数据集写法偏虚。`AutoCodeBench（ICLR 2026）论文对应评测数据集关键贡献者` 这句只证明你沾边，不证明你主导。招聘方天然会追问：你到底做了数据定义、构造、清洗、标注规范，还是只做了其中一小段？

[行动主张]
- 先砍。砍掉不服务目标岗位的教育荣誉堆叠，早期后端经历压缩到“证明工程底座扎实”即可；删掉未标注含义的账号；把 `接近0`、`高质量`、`数十篇` 这种虚词换成可定义表述。
- 再补。腾讯每条经历补齐 5 个要素：场景、你 own 的部分、规模、方法、结果口径。尤其补“离线评测如何对齐线上”“奖励函数优化什么”“样本如何筛选验收”“你是主导还是参与”。
- 再改。顶部定位改成单线程，例如“代码智能方向 LLM 评测与数据闭环工程师”。技能区只留你能在面试里展开讲透的词；`GRPO/RLHF` 如果讲不出实验设计、基线、收益归因，就降级成“参与后训练实验”。
- 结构上重排腾讯经历：评测体系建设 -> 数据构建 -> 后训练/线上验证。你最值钱的不是“我都会一点”，而是“我把一个场景从评测做到上线收益”。

[语言风格]
这份简历该像事故复盘，不该像名词仓库。少写“负责能力建设”“参与数据清洗”，多写“搭了什么机制、约束了什么口径、覆盖了什么规模、把什么指标从多少拉到多少”。一句话模板就是：在什么场景下，我主导了什么机制，基于什么数据和评测方法，最终把什么指标改善了多少，并支撑了什么决策。

[最大盲区]
你最大的盲区，是默认“关键词齐全 + 指标不少”就足以让人相信你真的做过 LLM 评测/数据/后训练闭环。不会。招聘方看的是证据链完整性，不是术语覆盖率：评测是否有效，数据是否可复用，训练是否可归因，线上收益是否能对上离线判断。你现在缺的不是经历，是把方法论讲硬。

[过度采用的风险]
如果按这个系统化思路改过头，简历会变成一张 KPI 面板：数字很多，人很薄。评测岗不只看你会不会搭链路，还看你能不能定义问题、和研发/产品对齐口径、在坏数据和坏指标进系统前就把它们挡住。

[签名句]
别急着堆关键词，先把“评测怎么准、数据怎么来、训练怎么验、线上怎么赢”的流程图画出来。
```
