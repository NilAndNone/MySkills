# radical_meme_dissident / 反建制梗学家

```text
[人格]
这份简历透出来的人设，不是“Prompt 皮套人”，而是“从日志、评测集、线上指标里抠结果的工程实干派”。好消息是像真干过活；坏消息是写法有点像 AI 年货拼盘，生怕少摆一个热词就显得不够时髦。

[核心判断]
只按提取文本看，不评价版式。这份简历最强的地方，是腾讯阶段确实出现了代码场景里的评测、数据、后训练、线上验证闭环，尤其代码补全那条有硬结果，不像纯 PPT 炼丹。它最像中高级 LLM 应用/评测工程师，偏评测基础设施和数据闭环，强于普通后端转 AI，弱于能独立定评测方法和训练路线的算法 owner。最大短板是定位没彻底收口：标题写“评测开发工程师”，内容却在“评测/应用/后训练”三套叙事之间来回横跳。

[问题诊断]
最硬的证据只有一条半。最硬的是代码补全闭环：线上数据到 `SFT+GRPO` 再到离线评测和线上采纳率提升，这条能证明你不只是搭台子；“34.8%→40.2%”也终于像业务结果。半条是代码审查与单测 Agent 评测：它们证明你会搭自动化评测，但还没证明评测本身“准不准、稳不稳、能不能真指导决策”。1347 条审查意见、2000+ 测试集、8 仓库这些规模不算寒酸，但也没到让人闭嘴的程度；面试官会追问覆盖度、标注标准、与人工一致性、污染控制、误报漏报。最容易被挑刺的点有四个：一是 `SFT/RLHF/GRPO/奖励函数设计` 这一串写得太满，像把高危关键词集体请上桌；二是 `CPO +30%` 未解释缩写，像故意留黑箱；三是 `AutoCodeBench` 的“关键贡献者”太虚，学术版“参与建设”；四是 `参与预训练数据清洗`、`数十篇报告` 这种表述信息密度低，像在给组织流程写感谢信。哈工大和竞赛奖是可信度加分，但对这个岗位只是封面烫金，不是主炮。

[行动主张]
先收口身份，建议改成“代码大模型评测与数据闭环工程师”或“LLM 应用工程师（评测/数据/后训练）”，别让招聘方替你做职业分类。再重排腾讯经历，把代码补全闭环放第一条，作为主战绩；代码审查评测和单测 Agent 评测放后面，但每条都补一个“评测有效性”指标和一个“业务决策”结果，不然就是自动化，不是评测方法。然后狠砍噪音：如果 `luxiaohan1997` 不是公开可验证账号名，就删；`数十篇报告` 删；`参与预训练数据清洗` 要么改成具体动作，要么删；Shopee 和鹏城压缩成工程底座，不要和腾讯主叙事抢镜。最后，能自证就写，不能自证就闭麦：如果 `GRPO/RLHF/奖励函数` 说不清数据来源、目标函数、负样本策略和收益归因，宁可少写一个热词，也别给面试官发开罐器。

[语言风格]
语言上别写成 AI 时代的奏折，要写成战报。少用“参与、支撑、建设、关键贡献者”这种组织安全词，多用“定义了什么、搭了什么机制、把哪个指标打成什么样”。最强那条甚至可以按这个方向重写：负责代码补全的数据与评测闭环，基于线上采纳日志构建训练/评测样本并设计奖励函数，完成 `SFT+GRPO` 迭代，推动 Python 采纳率由 34.8% 提升至 40.2%，`CPO` 提升 30%。这比“闭环建设”更像打过仗的人说话。

[最大盲区]
最大盲区是把“我碰过评测、数据、后训练流程”写成了“我已经是这三者的完整 owner”。现在文本真正站得住的，是“你做过真问题、真闭环、真线上指标”；还没充分站住的，是“你能定义评测方法、保证评测有效性、再把数据反哺训练”。换句话说，你像个有实战记录的前线军官，但简历却试图同时扮演参谋长、军需官和总设计师。

[过度采用的风险]
如果继续维持现在这套写法，招聘方很容易把你归类成“有大厂背景、做过一些 LLM 项目、但叙事偏泛的泛 AI 工程师”。这类人比纯后端转型者更强，但离“评测/数据闭环负责人”还差最后一锤。更现实的风险是，真正有价值的那条闭环成果还没展开，你已经先在 `GRPO`、`RLHF`、预训练清洗、`关键贡献者` 这些词上被连环盘问，简历自己给自己加了审讯灯。

[签名句]
历史不会重复台词，但会重复笑点。这份简历的笑点是：最硬的成果写得像附议，最虚的黑话却站在队伍前排。
```
